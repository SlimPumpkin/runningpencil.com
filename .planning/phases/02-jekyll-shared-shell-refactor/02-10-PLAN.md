2. 로컬 main 위에서 그 커밋들을 새 것부터 차례로 `git revert --no-edit`한다.
3. `scripts/check-site.sh HEAD`를 돌리고, `"$RP2/compare.sh" "$B" HEAD`로 출력이 기준과 같은지 확인한다.
4. **Task 3을 실패로 끝내고, 되돌리기 푸시는 따로 띄우는 `checkpoint:decision`으로만 승인받는다 (D-16).** Task 3은 `LIVE_PUSH4=OK`를 쓰지 않으므로 verify가 실패한다. 실행자는 FAIL 줄 전체와 1~3번 결과를 EVIDENCE의 `## 02-10 푸시 ④ 라이브 확인` 구간에 적는다. 그다음 인증 게이트처럼 그 자리에서 `checkpoint:decision`(gate="blocking-human")을 만들어 멈춘다. auto task 안에서 말로 승인을 묻지 않는다. D-16이 푸시 승인을 단계 중간에 멈추는 `checkpoint:decision`으로 정했기 때문이다. checkpoint의 내용은 다음과 같다.
   - decision: 로컬 main 끝(revert 커밋까지. 12자리를 문장에 적음)을 원격 main에 푸시할지 (main 푸시 = 라이브 배포)
   - context: FAIL 줄 전체, revert 커밋, 함께 나갈 커밋 목록 `git log --oneline origin/main..main`, 3번 결과
   - options: `rollback-push`(로컬 main을 푸시한다. 이 승인은 이 되돌리기 푸시 하나에만 쓰고, 앞뒤 어떤 푸시로도 이어지지 않는다), `other`(되돌리지 않고 다른 대응을 고른다. 그 결정을 EVIDENCE에 적고 멈춘다)
   - resume-signal: 「rollback-push」 또는 「other: <대응>」
5. 4번 checkpoint에서 `rollback-push`를 받은 뒤에만 이어서 실행한다. `git fetch -q origin main`으로 원격 main이 푸시한 커밋 그대로인지 확인한 뒤 `git push origin main`을 실행하고(훅 점검을 거침), `live-check.sh post <main 끝 커밋>`으로 복구를 확인한다. 주석을 되돌렸으므로 이 확인은 `--no-comments` 없이 한다.
6. force push, `git reset`으로 원격 이력 고치기, `--no-verify`는 쓰지 않는다. 원인 수정은 그다음 커밋에서 한다.
