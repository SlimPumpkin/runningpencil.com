1. 되돌릴 커밋: `git log --format=%H "$PREV..$PUSHED" -- . ':(exclude).planning'`(새 것부터). 로컬 main 위에서 차례로 `git revert --no-edit`한다. 충돌이 나면 `git revert --abort` 뒤 멈추고 보고한다.
2. `scripts/check-site.sh HEAD`가 통과하고, `git diff --quiet "$PREV" HEAD -- . ':(exclude).planning'`가 0인지 본다(트리가 문서 푸시 전과 같음). 실패하면 푸시하지 않고 멈춘다.
3. **Task 3을 실패로 끝내고, 되돌리기 푸시는 따로 띄우는 `checkpoint:decision`(gate="blocking-human")으로만 승인받는다.** FAIL 줄 전체와 1~2번 결과를 EVIDENCE의 `## 03-09 문서 푸시 라이브 확인` 구간에 적는다. options는 `rollback-push`(이 되돌리기 푸시 하나에만 쓰는 승인)와 `other`(다른 대응, EVIDENCE에 적고 멈춤)다.
4. `rollback-push`를 받은 뒤에만 `git fetch -q origin main`으로 원격이 푸시한 커밋 그대로인지 확인하고 `git push origin main`(훅 점검)을 한다. 배포 완료 뒤 같은 HTTP 확인을 다시 돌려 구간에 붙인다. 되돌려도 FAIL이 남으면 원인이 운영 환경에 있다는 뜻이므로 더 되돌리지 않고 멈춰서 보고한다.
5. force push, `git reset`으로 원격 이력 고치기, `--no-verify`는 쓰지 않는다.
</rollback_procedure>
