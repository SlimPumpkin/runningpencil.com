## 결정된 항목

### U12 — 지원 주소와 업무 메일 서비스

**상태:** 결정됨 (2026-11-14, 사용자)

결정 내용은 세 가지입니다 (D-10, D-11, D-19).

1. 슬림펌킨 업무 메일은 Google Workspace입니다. `runningpencil.com`을 Workspace에 사용자 별칭 도메인(user alias domain)으로 붙여서 지원 메일을 받습니다.
2. 지원 주소는 `support@runningpencil.com`입니다.
3. 지원 메일의 답장은 지원 주소에서 보냅니다. 그래서 `runningpencil.com`에 DKIM을 겁니다.

- **근거:** 업무 메일 도메인의 MX가 Google 값이고 SPF가 `include:_spf.google.com`이라는 `dig` 결과 (2026-11-14), `01-CONTEXT.md`의 D-10·D-11·D-19.
- **채택하지 않은 안:** 연구 단계의 기본안이던 별도 메일 전달 서비스는 채택하지 않았습니다.
- **남은 사용자 작업:** `.planning/baseline/USER-TASKS.md`의 작업 1~6 (사용자 별칭 도메인 추가, 가비아 DNS, `support` 주소 만들기, 외부 4곳 수신 시험, 지원 주소로 보내기 설정, DKIM).
- **되돌릴 때의 비용:** 메일 서비스를 바꾸면 DNS MX를 다시 바꾸고 이메일 게이트(외부 4곳 수신 시험)를 다시 거쳐야 합니다.

참고 (ROADMAP이 이미 결정된 것으로 적은 항목, 이 목록의 대상 아님): U1(전화번호는 이번에 공개하지 않고 칸만 마련), U4(영문 서비스명 RunningPencil), U10(포인트·굿즈·코스북 제거), U14(법적 문서 `noindex` 해제, `/en/` 홈페이지 포함).

## 항목별 풀이

### U2 — 위치정보법 분류

- **질문:** 러닝펜슬의 위치 처리가 위치정보법상 위치기반서비스사업(제9조 신고)인가, 위치정보사업(제5조 등록)인가?
- **근거:** 앱은 기기 GPS를 직접 받아 기록 중의 궤적을 `runs.path`로 저장합니다 (`firestore.rules:231-257`, `.planning/baseline/DATA-INVENTORY.md` 구간 C). 기기에서 위치를 직접 받는 앱의 분류는 조문만으로 정해지지 않습니다.
- **권장안:** 법률 확인을 받습니다.
- **기본 동작:** 위치약관을 위치기반서비스사업 신고 기준으로 씁니다. 위치정보사업 등록 대상으로 나오면 v2의 LOC-05로 보강합니다. 신고·등록을 실제로 할지는 사이트가 정하지 않고 마일스톤 인수 항목 ACPT-02로 둡니다. 「초안·법률 확인 필요」
- **결정 주체:** 법률 확인
- **막는 단계:** Phase 8 위치약관 범위, ACPT-02
- **마감 단계:** Phase 8 계획 전

### U3 — 소상공인·1인 창조기업 해당 여부

- **질문:** 슬림펌킨이 소상공인 또는 1인 창조기업에 해당하는가?
- **근거:** 코드 근거가 없는 사업자 사실입니다. 해당하면 개인정보 보호책임자 지정이 면제되고 대표자가 보호책임자가 됩니다 (`.planning/ROADMAP.md` Phase 7 External gates).
- **권장안:** 법률 확인을 받습니다.
- **기본 동작:** 처리방침에 개인정보 보호책임자 조항을 둡니다. 보호책임자의 이름과 연락처 값이 올 때까지 Phase 7 커밋을 보류합니다. 면제를 전제로 조항을 빼지 않습니다. 「초안·법률 확인 필요」
- **결정 주체:** 법률 확인
- **막는 단계:** Phase 7 보호책임자
- **마감 단계:** Phase 7 커밋 전

### U5 — Email/Password 가입 노출 여부

- **질문:** 앱 로그인 화면에서 Email/Password 가입을 계속 보이는가?
- **근거:** 이메일 가입은 지금 코드에서 화면에 드러나 있습니다.
  - 로그인 화면이 「이메일로 계속」 버튼(`EmailAuthCta`)과 회원가입 링크(`AppRoutes.signup`)를 조건 없이 그립니다 (`lib/features/auth/presentation/login_screen.dart:207`, `lib/features/auth/presentation/login_screen.dart:224`).
  - 저장소가 `signInWithEmailAndPassword`와 `createUserWithEmailAndPassword`를 부릅니다 (`lib/features/auth/data/auth_repository.dart:305`, `lib/features/auth/data/auth_repository.dart:368`).
  - dev Firebase 설정 기록에 「로그인 수단 (이메일 · 익명) — 기본대로 (이메일·익명 켜짐)」이 있습니다 (`docs/kit-fork.md:412`).
  - `enabledAuthProviders`는 소셜 제공자 6곳만 고르는 설정이고 `email`은 그 목록에 없습니다 (`lib/core/config/app_config.dart:314`). 이 설정으로는 이메일 로그인을 끌 수 없습니다.
  - 앱 저장소의 계획 문서(`.planning/PROJECT.md`, `.planning/REQUIREMENTS.md`)에는 이메일 로그인을 감춘다는 결정이 없습니다.
- **권장안:** 앱에서 이메일 가입을 계속 보일지 사용자가 정합니다. 계속 보이면 네이버 로그인 검수의 「별도 비밀번호 요구 금지」 항목과 부딪칠 수 있다는 점을 함께 판단합니다.
- **기본 동작:** 코드에 있는 대로 적습니다. 처리방침에 이메일·비밀번호(Firebase Authentication이 보관)와 인증 메일 발송을 넣습니다.
- **결정 주체:** 사용자(앱)
- **막는 단계:** Phase 7
- **마감 단계:** Phase 7 커밋 전

### U6-가 — 탈퇴 후 공개 코스 유지

- **질문:** 탈퇴한 사용자의 공개 코스를 남기는 지금 방침을 그대로 가는가?
- **근거:** 앱의 결정은 「courses 는 남김(공개 자산, `creatorId` 만 남음)」입니다 (앱 저장소 `.planning/phases/02-foundation-kit-fork/02-CONTEXT.md:66`). 탈퇴 정리 함수의 주석도 「남기는 것: 공개 코스 자산」이라고 적습니다 (`functions/src/running_pencil/cleanup_user_data.ts:20`).
- **권장안:** 유지합니다. 삭제 안내와 약관에 탈퇴 뒤에도 남는 데이터로 밝힙니다.
- **기본 동작:** 코드대로 적습니다. 공개 코스는 탈퇴 뒤에도 남는다고 안내합니다.
- **결정 주체:** 사용자(앱)
- **막는 단계:** Phase 6, Phase 8
- **마감 단계:** Phase 6 커밋 전

### U6-나 — 탈퇴 후 비공개 코스 처리

- **질문:** 탈퇴 때 비공개 코스도 지우도록 앱을 고치는가? 고치지 않으면 삭제 안내에 비공개 코스도 남는다고 적는가?
- **근거:** 지금 코드대로면 비공개 코스도 탈퇴 뒤에 남습니다.
  - `cleanupUserData`는 `runs`와 `users/{uid}/badges`만 지웁니다 (`functions/src/running_pencil/cleanup_user_data.ts:17-21`). `functions/src` 전체에 코스를 지우는 코드가 없습니다. 앱 쪽 탈퇴도 `deleteUserAccount` 호출 하나뿐입니다 (`lib/features/settings/data/settings_repository.dart:104`).
  - 비공개 코스에는 경로(`polyline`, `waypoints`, `sketchPolyline`), 출발점(`startPoint`), 지역(`region`), `creatorId`가 있습니다. 비공개 코스는 만든 사람만 읽을 수 있어서 (`firestore.rules:320-321`) 탈퇴 뒤에는 어떤 사용자도 읽지 못하고 관리자 권한으로만 보입니다.
  - 사용자가 탈퇴 전에 코스를 한 건씩 직접 지울 수는 있습니다 (`lib/features/courses/data/course_repository.dart:327`, `firestore.rules:332`).
- **권장안:** 앱에서 탈퇴 때 비공개 코스를 지우도록 고칩니다. 읽을 수 있는 사람이 없는 경로 데이터가 기한 없이 남기 때문입니다. 앱 저장소의 일이라 사용자가 정합니다.
- **기본 동작:** 코드대로 적습니다. 삭제 안내에 공개·비공개 코스가 모두 남는다고 안내합니다. 앱이 고쳐지면 데이터 목록의 재확인 규칙(D-09)으로 목록과 안내를 고칩니다.
- **결정 주체:** 사용자(앱)
- **막는 단계:** Phase 6, Phase 8
- **마감 단계:** Phase 6 커밋 전

### U7 — 만 14세 미만 가입 정책

- **질문:** 만 14세 미만의 가입을 제한하는가, 법정대리인 동의를 받는가?
- **근거:** 앱에서 나이 확인 단계를 찾지 못했습니다. 약관 동의 기록의 키는 `service`, `privacy`, `marketing`뿐입니다 (`firestore.rules:54-64`). 나이 입력 화면이 있는지는 「미확인」입니다.
- **권장안:** 법률 확인과 함께 사용자가 정책을 정합니다.
- **기본 동작:** 만 14세 미만의 가입을 받지 않는 정책으로 약관과 처리방침 초안을 씁니다. 앱에 나이 확인 단계가 없다는 사실을 사용자에게 함께 알립니다. 「초안·법률 확인 필요」
- **결정 주체:** 사용자·법률 확인
- **막는 단계:** Phase 7, Phase 8
- **마감 단계:** Phase 7 커밋 전
